# Como interpretar problemas

Antes de pensar no código, transforme o enunciado em uma tarefa objetiva.

1. Identifique exatamente o que deve ser calculado ou decidido.
2. Separe os dados de entrada e observe quantos casos existem.
3. Anote o formato exato da saída.
4. Leia os limites: eles ajudam a escolher uma abordagem viável.
5. Refaça os exemplos no papel e confira cada etapa.
6. Crie casos pequenos, extremos e diferentes dos exemplos oficiais.

Depois, descreva a solução em frases ou passos. Se os passos ainda estiverem
ambíguos, o código provavelmente também ficará.

## Perguntas úteis

- O problema possui um caso ou vários?
- A entrada termina após uma quantidade conhecida ou em EOF?
- Existe empate, entrada mínima ou outro caso especial?
- A ordem dos dados importa?
- A saída exige uma linha para cada caso?
