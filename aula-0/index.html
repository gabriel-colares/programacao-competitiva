O que é Maratona de Programação?

  • Maior competição universitária do BR
  • Equipes de 3 pessoas, 5 horas de prova
  • 1 computador por equipe
  • Sem internet, só material impresso
  • Caderno de 12~13 problemas
  • Vence quem resolver mais problemas

Metas do IFAM

  • Formar equipes constantes
  • Preparar turmas para OBI e competições online
  • Criar uma cultura de treino contínuo

O que são problemas Ad-Hoc?

  • Em latim: “ad hoc” = “para isto”
  • Problemas que não se encaixam em uma categoria específica
    • Estruturas, Strings, Grafos, Matemática, Geometria, Paradigmas (Prog. Dinâmica, Gulosos, Backtracking, ...)
  • Geralmente simulações da vida real, jogos, data e hora, etc
  • Costumam ter uma historinha bem chata, tipo ENEM
    • E geralmente são os problemas mais fáceis da prova
  • Exemplo de questão Ad-Hoc: Beecrowd 1467
08

O que NÃO fazer na Maratona (e OBI)

  • “Conversar” com o usuário
    • Ex.: “Digite o número A:”
  • Não ler o enunciado do problema com calma
  • Assumir algum fato sobre a solução na pressa
  • Não reler os limites do problema antes de submeter
  • Dividir por zero (runtime error)
  • Alocação dinâmica manual (malloc, new)
    • Prefira usar arrays estáticos ou vector<>, por exemplo
  • Declarar vetor com tamanho insuficiente
  • Não conferir se a saída está formatada corretamente
09

Dicas para compilar e testar

  • Use o editor de texto da sua preferência
    • VSCode, Sublime Text, Geany, Gedit, etc
  • Compile usando a linha de comando do Linux (ou WSL)
    • C++:
      • g++ -Wall -std=c++17 arquivo.cpp
      • time ./a.out < arquivo.in > my.sol
      • diff arquivo.sol my.sol
    • Python
      • time python3 arquivo.py < arquivo.in > my.sol
      • diff arquivo.sol my.sol
